# 变更回归计划 v1.1（CR-03 认领列表分组）

基线：V1.0.1（`c62a0b2`）。实施方：前端会话。本计划只覆盖**呈现层**回归；
后端历史证据（49 unit / 118 integration / 11 performance）保持有效，不重跑、不重述。

## 1. 范围

| 纳入 | 理由 |
| --- | --- |
| FR-10 分组与计数 | 本次唯一新增行为 |
| FR-01 列表与分页 | 列表读取方式由“混合”改为“分组”，需确认分页不串 |
| QR-02 身份切换与越权 | 分组不得让上一身份或他人数据出现 |

**不纳入**：后端状态机、唯一获批、双向码、幂等、匹配规则 `rules-v1.1`、性能全套压测。
理由：CR-03 无后端改动；重复全套性能测量没有信息增量。若前端引入明显多余的请求，再单独立项。

## 2. 环境与数据

- 前端：`web/index.html`、`web/styles.css`、`web/app.js`（仅这三文件可改）。
- 后端：`python -m uvicorn app.main:app --port 8000`，`.env`（claim_dev），`DEMO_MODE=true`。
- 身份：alice（申请人）、bob（申请人，用于交叉）、finder（拾获方）、outsider（越权）。
- 数据：`python scripts/seed_demo.py --database dev` 的 8 条演示记录即可；测试中产生的认领可保留，
  但不得手工改库来“凑”计数。

## 3. 用例

| 编号 | 场景 | 步骤 | 期望 |
| --- | --- | --- | --- |
| RG-01 | 默认分组 | 以 alice 打开“我的认领” | 默认选中“我发起的”，列表与高亮一致 |
| RG-02 | 计数准确 | 分别记录两组 `total` 与 `GET /v1/claims?role=applicant/finder` 的 `total` | 两组数字与接口逐一相等；不出现估算值 |
| RG-03 | 切换同步 | 在两组间快速来回切换 3 次 | 列表与计数始终对应当前组；无旧响应覆盖 |
| RG-04 | 分页不串 | 构造 >20 条后翻到第 2 页，再切组 | 第 2 页内容属于该组；切组后回到第 1 页 |
| RG-05 | 空组说明 | 用 outsider（无任何申请）打开 | 两组均给出空态说明，不显示误导性 0 条记录 |
| RG-06 | 身份切换 | alice → bob → outsider，每次切换后立即查看 | 列表清空重拉；不残留上一身份的标题、计数或详情 |
| RG-07 | 越权 | outsider 直接打开他人 claim 详情/会话 | 服务端 403；列表不含他人申请；前端只显示错误态 |
| RG-08 | 混合入口移除 | 检查界面入口；另抽查 `role=all` | 界面无“全部”入口；`GET /v1/claims?role=all` 仍返回 200（兼容保留） |
| RG-09 | 计数失败占位 | 断网或拦截 `/v1/claims` 后切组 | 计数显示“—/暂不可用”，**不得显示 0**；恢复后自动刷新 |
| RG-10 | 不双计 | 取两组列表的全部 `id` | 两组无交集；去重后总数 = 该用户相关申请总数 |

## 4. 进入与退出准则

**进入**：前端三文件已改完；后端在 8000 端口可访问；`/health` 返回 200。

**退出**：RG-01~RG-10 全部通过；无控制台未捕获异常；无 5xx；回滚脚本可用。
未满足则保持 `Accepted-PendingVerification`，不得标记 verified。

## 6. 失败处理与回滚

1. 计数与列表不一致：先查是否残留过期响应（应带分组标记丢弃），再查是否读取了缓存。
2. 身份串数据：立即停止发布，清空前端缓存后复测；仍失败则回滚。
3. 回滚：`git checkout c62a0b2 -- web/index.html web/styles.css web/app.js`，刷新即可；后端与数据不动。

## 7. 风险

| 风险 | 观察点 |
| --- | --- |
| 两组合计与“全部”口径混淆 | 两组合计是“去重后的本人相关申请”，不是两个 total 的简单相加 |
| 计数请求失败被吞 | RG-09 必须看到占位符而非 0 |
| 深链/刷新落到错误分组 | 刷新后仍停在当前组，或显式回到默认组并给出提示 |
| 旧缓存跨身份 | 切换身份必须清空私有数据 |
