# 失物认领子系统 需求规格说明书 v1.1

基线：V1.0.1（commit `c62a0b2`）。v1.1 只新增 FR-10（认领列表分组），其余需求沿用 v1.0.1
的版本、验收口径与既有证据，**不宣称因本次变更重新测过**。

标记：**【VP-Adopted】** 采纳自需求讨论的建议；**【Revised】** 经用户修订；**【Rejected】** 已否决。

## 1. 范围

**做**：认领管理、匿名沟通、可解释规则匹配、交接确认。
**不做**：失物/招领发布与编辑、账号注册与校园实名、争议裁决、系统管理后台、推送、物流。

外部依赖只有两类只读接口：身份（令牌校验）与招领/失物数据。真实对接前使用带 `origin=demo`
标识的本地快照，**不宣称已接入其他成员系统**。

## 2. 角色

| 角色 | 说明 | 系统内可见 |
| --- | --- | --- |
| 申请人 | 发起认领的一方 | 自己的申请、本申请的私有证据与会话 |
| 拾获方 | 招领记录的发布者 | 本记录收到的申请、证据与会话 |
| 无关用户 | 已登录但非本申请双方 | 仅公开列表字段 |
| 管理员 | 线下接收争议导出 | 系统内**无任何权限** |

真实姓名、手机号、学号不进入本系统；双方只看到会话别名。

### 3.1 FR-10 细则（Accepted-PendingVerification）

1. 默认分组为“我发起的”，另一组为“我收到的”。
2. 两组分别调用 `GET /v1/claims?role=applicant|finder`，`total` 必须来自响应，不得前端估算。
3. 移除“全部/混合”入口；**API `role=all` 保留**以兼容旧调用，服务端不改。
4. 切换分组、刷新、切换身份时列表与计数同步更新；计数读取失败显示“—/暂不可用”，不得显示 0。
5. 同一申请不得双计；组内保留角色标签、分页与空组说明。
6. 分组只是呈现与默认筛选，越权仍由服务端 403 拦截。
7. 实施只改 `web/index.html`、`web/styles.css`、`web/app.js`；无数据库、状态、认证与 schema 变更。
8. 状态：**Accepted-PendingVerification**。在 UI 测试记录回填前，不声称已验证。

### 3.2 认领状态机

`PENDING → APPROVED | REJECTED | WITHDRAWN | CLOSED_OTHER | EXPIRED`
`APPROVED → COMPLETED | DISPUTED | EXPIRED`
其余为终态；非法迁移 409；终态不吸收事件。

## 5. 开发约束与接口澄清

1. Python + FastAPI + SQLAlchemy + PyMySQL + 真实 MySQL（禁止 SQLite 替代）。
2. 只读其他成员数据；不实现发布、注册、管理员裁决。
3. 不引入在线大模型、向量数据库、付费 API；不接学校真实服务作为本期依赖。
4. 单机本地可演示；不拆服务、不上消息中间件。

**5.1 接口澄清（沿用 V1.0.1）**：重置交接码的 `reason` 可选；驳回与争议的 `reason` 必填且
`strip()` 后非空。该口径自 V1.0.1 起采用，不表示 V1.0 曾强制。

**5.2 兼容性**：FR-10 无接口与 schema 变更；`role=all` 保留。

## 7. 风险

1. 匹配 0.975 来自合成数据与已见回归集，不代表真实校园准确率。
2. 性能仅本机、单进程、20 并发，不能外推公网。
3. 聊天限流为单进程内存；交接码密钥轮换未实现。
4. FR-10 的计数依赖前端正确丢弃过期响应，存在短暂不一致的可能。
5. 别名不阻止用户主动自报身份；平台侧仍可按内部 `user_id` 关联。
