# 变更影响分析 v1.1（CR-03）

基线：V1.0.1（`c62a0b2`）。唯一进入实施的变更是 CR-03「认领列表分组」。
结论先行：**只影响呈现层**——无数据库、状态机、认证、匹配规则、DTO 或接口 schema 变更；
`GET /v1/claims` 的 `role=all` 保留兼容；回滚只需回退前端三文件。

## 1. 按 RTM 各列的逐项影响

| RTM 列 | 是否变化 | 影响说明 |
| --- | --- | --- |
| 需求ID | 新增 FR-10 | 现有 FR-01~FR-09、QR-01~QR-06 的 ID 不变 |
| 版本 | 仅 FR-10 为 1.1 | 其余需求保持 1.0 / 1.0.1 及其原证据，不因本次呈现调整而升级 |
| 变更状态 | 仅 FR-10 为 Accepted-PendingVerification | 其余行的“已通过”证据不被复用、也不被撤销 |
| 设计模块 | 新增“认领列表分组（呈现层）” | 不新增后端模块；`claim_service.list_claims` 不变 |
| 实现文件 | 新增 `web/index.html`、`web/styles.css`、`web/app.js` | 后端 `app/` 零改动 |
| 测试用例 | 新增待填的 UI 用例编号（RG-xx） | 现有 unit/integration/performance 用例不受影响，也不重跑 |
| 证据 | FR-10 待回填；其余行沿用 V1.0.1 证据 | 不新增、不覆盖既有证据文件 |
| 说明 | FR-01 增加一行“呈现受影响，回归见计划” | 不改变 FR-01 的版本与证据 |

## 2. 按需求行的逐项影响

| 需求 | 影响 | 处理 |
| --- | --- | --- |
| FR-01 发起认领 | **间接**：列表呈现改为两组，`GET /v1/claims` 的调用方式与分页需回归 | 回归 RG-02~RG-05；后端不变 |
| FR-02 私有证据 | 无 | 证据可见性仍由服务端判定 |
| FR-03 核验与批准 | 无 | 批准仍在详情页；列表只做入口 |
| FR-04 多申请与唯一获批 | 无 | 不变 |
| FR-05 撤销 | 无 | 不变 |
| FR-06 匿名沟通 | 无 | 不变 |
| FR-07 交接确认 | 无 | 不变 |
| FR-08 规则匹配 | 无 | 不变 |
| FR-09 争议导出 | 无 | 不变 |
| **FR-10 认领列表分组（新）** | **新增** | 默认“我发起的”，可切“我收到的”；各组准确 `total`；移除混合入口；`role=all` 保留 |
| QR-01 性能 | 无后端影响 | 不重跑全套；若前端请求数明显增加再单独评估 |
| QR-02 匿名性 | **间接**：身份切换与越权呈现需回归，分组不得让上一身份数据残留 | 回归 RG-06、RG-07 |
| QR-03 过滤 | 无 | 不变 |
| QR-04 匹配评测 | 无 | 规则与评测集不动 |
| QR-05 令牌 | 无 | 不变 |
| QR-06 码与幂等 | 无 | 不变 |

## 3. 接口与数据兼容性

- **无新增/删除路径**，无请求或响应字段变化，无数据库迁移。
- `GET /v1/claims?role=applicant|finder|all&page=&page_size=` 三种取值全部保留；前端默认使用前两者。
- 分页结构 `{items,total,page,page_size}` 不变；两组各自独立分页。
- 权限模型不变：越权仍由服务端 403 拦截，前端分组不是授权手段。

## 4. 回滚方案

1. 触发条件：分组计数与列表不一致且无法在验收窗口内修复；或身份切换出现数据串扰。
2. 步骤：`git checkout c62a0b2 -- web/index.html web/styles.css web/app.js`，刷新页面即可。
3. 影响面：仅前端呈现；后端与数据无需回滚，已产生的认领数据不受影响。
4. 回滚后仍保留 `role=all` 的 API 兼容性。

## 5. 明确不受影响

后端 7 张表、状态机、锁序、唯一获批指针、双向码、幂等、匹配规则 `rules-v1.1`、
评测集与标签、`.env` / `.env.test`、测试协作者的 `tests/integration` 与 `tests/performance`。
